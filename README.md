# Оптимізація системи охолодження дата-центру на основі прогнозування обчислювального навантаження.

Цей проєкт присвячений моделюванню та прогнозуванню витрат електроенергії на охолодження (HVAC) серверної інфраструктури комерційного дата-центру. Мета роботи — знайти компроміс між економічними витратами та стабільністю роботи обладнання за допомогою точного прогнозування навантаження.

## 📋 Опис задачі
У дата-центрах системи клімат-контролю споживають значну частину енергії. Ця модель аналізує історичне завантаження процесорів (CPU) та зовнішні погодні умови, щоб з високою точністю спрогнозувати необхідну потужність охолодження на майбутні періоди.

* **Об'єкт дослідження:** Серверний вузол (кластер) підприємства.
* **Економічний критерій:** Мінімізація витрат на електроенергію для кондиціонування.
* **Екологічний критерій:** Зменшення енергоспоживання та викидів СО2 за рахунок уникнення холостої роботи компресорів.

## 🛠 Технологічний стек
* **Мова програмування:** Python 3
* **Основні бібліотеки:** Pandas (обробка даних), NumPy (математичні операції), Matplotlib (візуалізація), Scikit-Learn (машинне навчання).
* **Середовище виконання:** Jupyter Notebook / Google Colab.

## 💾 Дані
Для навчання моделі використовується вибірка з реального датасету **Google Cluster Workload Traces (2019)** (файл `borg_traces_data.csv`).
Оскільки в серверних логах відсутня інформація про погоду, алгоритм накладає на дані реалістичну метеорологічну модель (зміна дня/ночі та сезонні коливання) для проведення Feature Engineering (конструювання ознак).

*Примітка: У коді передбачено механізм fallback: якщо файл `borg_traces_data.csv` не знайдено, скрипт автоматично згенерує синтетичні дані для безперебійного тестування пайплайну.*

## 🚀 Як запустити проєкт
1. Відкрийте платформу Google Colab.
2. Завантажте файл `borg_traces_data.csv` у кореневу папку файлового менеджера Colab (меню зліва).
3. Скопіюйте код проєкту в комірку (або завантажте файл `.ipynb`).
4. Натисніть `Run All` (Запустити все).

## 🧠 Архітектура моделі
В якості ядра прогнозування використовується ансамблевий алгоритм **HistGradientBoostingRegressor** (Гістограмний градієнтний бустинг).

**Ключові налаштування (Гіперпараметри):**
* `max_iter=600`: Кількість побудованих дерев рішень.
* `learning_rate=0.02`: Зменшений крок навчання для уникнення перенавчання (overfitting).
* `max_leaf_nodes=63`: Глибина дерев для виловлювання складних нелінійних залежностей.
* `l2_regularization=0.5`: L2-штраф за занадто великі ваги, згладжує прогноз при аномальних скачках CPU.

Для роботи з часовими рядами (Time Series) використано **Лагові ознаки (Lag Features)** — модель "дивиться" на стан серверів 5 та 15 хвилин тому (`CPU_Lag1`, `CPU_Lag3`), а також враховує синергію спеки та завантаження (`Temp_CPU_Interaction`).
